Browser fork acceptance worksheet

Record four marker reads to check whether a paused Cloudbrowser fork copied persistent state and kept later writes separate.

Collect observations

  1. In a test browser you control, write before-fork to a harmless persistent marker on a test origin.
  2. Pause the source before creating the fork. Resume the two browsers separately and read the marker in the child.
  3. Write child-only in the child. Read the original marker again in the source.
  4. Write source-only in the source. Read the child and source again through their separate connections.

Use the same origin for all reads and writes. If you use a cookie, set an explicit expiry and keep its path in scope. The worksheet checks recorded observations. Use separate tests for website login or in-memory page state.

Evaluate the marker reads

Browser marker inputs stay on this page. If a read fails, check that pause completed, verify the origin and expiry, and confirm that the source and child connections refer to different browsers.
